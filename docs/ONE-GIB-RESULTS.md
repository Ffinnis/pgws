# Тест PGWS на базе 1 ГиБ

20 сентября 2026 года тест `TestLiveDaemonsOneGiB` прошёл за 236,26 секунды.
Полный журнал и измерения сохранены в [one-gib-lab.json](../evidence/one-gib-lab.json).

Запуск для повторения:

```sh
python3 scripts/host_lab.py --one-gib
```

Тест использовал отдельные source и management базы, процессы API, worker,
host и guard, контейнеры PostgreSQL 18.6 и временный ZFS-пул размером 4 ГиБ.
Среда: Lima, Ubuntu 24.04 ARM64, 4 CPU, 8 ГиБ RAM, OpenZFS 2.2.2.
Существующий сервис разработки сохранился. Временный пул и контейнеры удалены.

| Измерение | Результат |
| --- | --- |
| Размер source по `pg_database_size` | 1 076 975 295 байт, около 1,003 ГиБ |
| Строк в основной таблице | 516 096 |
| Случайные данные в payload | 980 582 400 байт |
| Генерация source | 11,79 с |
| Начальная загрузка baseline | 113,475 с |
| Создание клона 1 / 2 / 3 | 2,164 / 3,642 / 5,308 с |
| Полная проверка данных клона 1 / 2 / 3 | 2,846 / 2,657 / 3,224 с |
| ZFS used до клонов | 1 067 154 944 байт |
| ZFS used с тремя клонами до пользовательских записей | 1 070 048 256 байт, прирост 2,76 МиБ |
| ZFS used после независимых записей | 1 083 821 056 байт, прирост 15,89 МиБ от baseline |
| ZFS used после удаления клонов | 1 067 550 720 байт |

Три запроса создания поступили до ожидания результата. Их обслуживал один
worker; все три клона работали одновременно. Время создания включает очередь
и заканчивается сохранённой отметкой завершения операции в management базе.
Полная проверка данных измерена отдельно. Начальная загрузка использовала
существующее ограничение `pg_basebackup` в 10 МиБ/с.

Каждая строка содержит 1900 случайных байт с PLAIN storage. Полные проверки
сравнили количество строк, суммарный размер payload и MD5 каждой строки до
и после изменений. MD5 здесь служит только для проверки целостности данных.

Прошли следующие проверки:

- Подключение к настоящему PostgreSQL через TLS с `verify-full`.
- Независимые изменения в трёх клонах, сохранность исходной базы и данных соседей.
- Pause закрывает открытое соединение; resume сохраняет изменения.
- Reset создаёт новое поколение, удаляет изменения и восстанавливает данные baseline.
- Удаление всех трёх клонов подтверждается завершёнными операциями.
- SIGKILL host во время создания и SIGKILL host вместе с guard с последующим восстановлением прежнего SQL endpoint.
- Полный жизненный цикл через Python SDK, barrier и `at_least`.
- Отзыв principal token закрывает его SQL-сессию за 0,953 с; отзыв raw grant закрывает соединение за 1,007 с.
- Давление на ZFS-пул закрывает SQL за 1,938 с, удаляет принадлежащий источнику replication slot и сохраняет terminal stop после освобождения места.

Для этой базы обнаружился прежний фиксированный лимит начальной загрузки
512 МиБ. Добавлен параметр `seed_max_bytes` с проверкой квот; значение по
умолчанию осталось прежним. В тесте установлен бюджет 1536 МиБ и квота проекта
4 ГиБ. Квота baseline учитывает архив, распакованную копию и запас 256 МиБ.
Бюджет сохраняется с поколением и не может меняться при повторном выполнении.

Счётчики ZFS отражают состояние в моменты замеров. Тест не принуждал checkpoint
клонов или `zpool sync`, поэтому это не измерение пикового занятого места либо
полной стоимости всех записей после их сброса. Резерв памяти для baseline и
трёх клонов составлял 4 ГиБ; фактический RSS не измерялся. Этот один прогон
не определяет p95/p99 и не заменяет предусмотренный RFC тест 1 ТБ / 14 клонов.

Первый запуск остановился из-за ошибки самого теста: он ожидал `completed_at`
в публичном API операций. Измерение исправлено на чтение сохранённой отметки
из изолированной management базы. Журнал первого запуска сохранён отдельно
в `evidence/one-gib-initial-fixture-failure.json`.

После изменений прошли `go test -race ./...`, `go vet ./...` и интеграционные
SQL/API/lifecycle проверки `python3 scripts/integration.py`.
Дополнительно прошли три проверки `TestLiveSourceRecovery` с SIGKILL на этапах
`runtime`, `backup` и `seed`, суммарно за 58,97 секунды. Они проверяют
восстановление начальной загрузки с прежним бюджетом по умолчанию.
