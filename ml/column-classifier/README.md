# Offline column classifier training

This pipeline trains review-only candidates from scratch with the shared Go
encoder. It does not include a licensed corpus or a qualified release model.
`smoke.py` exercises the whole pipeline using authored synthetic fixtures and
deletes its weights and signing key. Its scores do not measure real-world quality.

Use Python 3.12 and the hash-locked requirements. From the repository root:

```sh
uv venv --python 3.12 .local/classifier-venv
uv pip sync --python .local/classifier-venv/bin/python ml/column-classifier/requirements.txt
make classifier-lab
make build
.local/classifier-venv/bin/python ml/column-classifier/train.py reviewed.ndjson candidate --features bin/pgws-features
```

The output directory must not exist. Training creates it with mode 0700.
Records must satisfy `contracts/classifier/training-record.schema.json`, carry
review/provenance declarations and contain no raw row values. The importer
rejects duplicate IDs, unknown fields, duplicate JSON keys and non-finite JSON
numbers. Limits are 30,000 records, 128 KiB per record and 512 MiB per dataset.
Default runs require at least 100 declared application families. These
declarations still need human provenance review; changing a family ID does not
make a fork or generated variant independent. See [annotation guide](ANNOTATION.md).

Public runs require redistribution approval on every record and reject private
origins. `--private` explicitly allows consented private profiles; all resulting
artifacts must stay within their approved boundary. Neither flag proves legal
rights or removes sensitive literals from schema identifiers.

Family IDs determine a stable hash-sorted split: 65% training, 10% development,
5% temperature fitting, 5% threshold reporting and 15% test. All 24 classes must
occur in training. SAGA fits L2 multinomial logistic regression with C values
0.1, 1 and 10, comparing no class weighting with training-only weights capped at
5. Non-converged candidates fail. Development loss selects the candidate.
Temperature uses its own partition after FP32 export. Test data cannot select
parameters. The threshold partition currently produces a report only.

Outputs contain raw little-endian FP32 arrays, the split, a manifest, a model
card and up to 128 held-out parity profiles/scores. No pickle files are written
or read. The model card includes per-class metrics, confusion, ten-bin ECE,
log loss and family coverage. Family-cluster uncertainty, subgroup evaluation,
full rules/policy-path quality and automatic thresholds remain unqualified.

After reviewing the candidate and retaining the referenced provenance/card,
sign its exact bytes with a separately managed operator key:

```sh
bin/pgws-model-pack candidate/manifest.json candidate/weights.f32 candidate/bias.f32 /private/release.key candidate.model
bin/pgws-classify candidate.model /private/release.pub < candidate/parity-profiles.ndjson
```

Keys are base64 Ed25519 files with mode 0600, private key 64 bytes and public key
32 bytes after decoding. The signer verifies the manifest checksums and runtime
contract, validates its signed output through the loader, and refuses existing
output paths. Production signing keys are never generated by training.
Signing does not qualify the candidate or enable automatic acceptance.

The smoke run checks family partition isolation, input rejection, training,
export, ephemeral signing, no-overwrite and all Python/Go scores within 1e-5.
It records only engineering evidence in `evidence/classifier-lab.json`.

[NumPy 2.4.4](https://numpy.org/devdocs/release/2.4.4-notes.html),
